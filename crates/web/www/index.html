The protocol

8 prompts × 3 paired repetitions per length, the order rotating between arms, one warm-up per arm discarded. The speed-up is native ÷ bridge, the geometric mean over prompts, with its 95% interval (documents/REPRODUCTION.md §5). The ceiling is the answering model alone ÷ the reading model alone: the most the bridge could gain. The bridge arm's own reading of the prompt is inside its time; nothing is excluded. Every run's counters are recorded, so you can check that native runs read the prompt and bridged runs did not.

One reply, bridged

The small model reads

SmolLM2-135M reads every prompt token but the last, building its key/value memory, layer by layer.

The bridge translates

For each layer of the 360M, a fitted ridge map turns the 135M's residual stream into the keys and values the 360M would have built, then the paper's rank-4 learned correction refines them.

The larger model reads one token

The 360M takes that memory as its own and reads exactly one token of the prompt itself: the bridge token.

It answers

The 360M generates as usual. It skipped reading the prompt, which is where the time goes on a long one, so its first token arrives sooner.

The words on this page

Time to first token
From pressing Ask to the first token the answering model samples. The bridged time includes the small model's reading.
Bridge token
The one token of your prompt the larger model reads itself, on top of the translated memory.
Ceiling
The larger model alone ÷ the small model alone: the most any handoff could gain, since the small model still has to read.
NCR
The paper's native-closure ratio: of the gap between the larger model reading nothing and reading everything, the share the bridge closes, scored on the larger model's own replies.
Wrong memory (donor)
The control: the same bridge fed another question's memory. A real bridge's answer changes with it.
95% interval
The range the paired speed-up's geometric mean falls in across prompts, LatentPort's own statistic.

1.87× sooner, and how it is measured

Time to first token for the bridged 360M against the 360M reading the whole prompt, on the same machine, in the same tab: 8 prompts × 3 paired repetitions, the arm order rotating, one warm-up per arm discarded.

The figure is the geometric mean of native ÷ bridged over prompts with its 95% interval, LatentPort's own statistic. The bridged time includes the 135M reading the prompt.

One bridge token

LatentPort's handoff: the larger model reads exactly one token of the prompt itself, and everything before it arrives as translated key/value memory.

The page reads the counts from the models themselves on every reply: prompt tokens, tokens the 135M read, prompt history the 360M read, and bridge tokens.

6 of 7 held-out questions

Seven questions never used in fitting, each with one checkable answer. Bridged, the 360M gets 6 right, as many as the 360M reading everything. With the ridge maps alone, before the paper's learned correction, it kept only the shape of an answer: 3 of 7.

Fidelity on held-out replies: NCR 0.930. The paper's corrected bridge, on its own pair: 0.918.

The result →

Time to first token

From pressing Ask to the first token. With the bridge off, the 135M answers alone; with it on, the 360M answers from the 135M's memory, so these two times compare different models. The fair comparison is on the Measure tab.

The counters

Reported by the models after each reply, not computed by the page: how many prompt tokens the reading model read, how much prompt history the answering model read, and how many bridge tokens it read itself.

Bridged, the 135M reads all but the last token, the 360M reads none of the prompt, and one bridge token crosses.

Why these controls

An answer that looks right could come from the one token the 360M reads, not the memory. So the same question runs with a different question's memory: if the answer changes, it was reading the memory.

Restoring the 135M's own memory must reproduce its reply exactly, which shows the memory is moved without loss. Each run is capped at 32 tokens.

NCR, the native-closure ratio

(ℓ_empty − ℓ_bridged) / (ℓ_empty − ℓ_native), the paper's Eq. 8: each ℓ is the larger model's loss on its own native reply. 1 means the bridged model is as sure of that reply as when it reads everything.

Read it beside each card's wrong-memory control: where an empty model is very far off, any memory scores high.
